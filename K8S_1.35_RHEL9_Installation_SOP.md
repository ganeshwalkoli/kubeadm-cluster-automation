# Kubernetes 1.35.X Installation SOP on RHEL 9.6

This Standard Operating Procedure (SOP) details the steps to install and configure a production-grade Kubernetes 1.35.x cluster on Red Hat Enterprise Linux (RHEL) 9.6 using `kubeadm` and `containerd`, with Calico as the CNI.

---

## 0. Prerequisites: Security Groups / Firewall Ports
Before starting, ensure your AWS Security Groups (or equivalent network firewalls) allow the following traffic between your instances. 

### Control Plane Node - Inbound Rules

| Port | Protocol | Source (From) | Destination (To) | Simplified Purpose |
| :--- | :--- | :--- | :--- | :--- |
| **6443** | TCP | Worker Nodes, Admins | Control Plane Node | **API Server:** The main entry point. Allows workers to join and admins to run `kubectl`. |
| **2379-2380** | TCP | Other Control Planes | Control Plane Node | **etcd:** The cluster database. Used *only* if you add a 2nd/3rd Control Plane node for HA. |
| **10250** | TCP | Control Plane, Workers | Control Plane Node | **Kubelet:** Allows fetching pod logs and executing commands on the Control Plane node. |
| **10259** | TCP | Control Plane Node | Control Plane Node | **Scheduler:** Internal secure port. Leave closed unless using external Prometheus scraping. |
| **10257** | TCP | Control Plane Node | Control Plane Node | **Controller Manager:** Internal secure port. Leave closed unless using external Prometheus. |
| **179** | TCP | Worker Nodes | Control Plane Node | **Calico BGP:** Shares the "map" of where pods live so the Control Plane can route traffic. |
| **4789** | UDP | Worker Nodes | Control Plane Node | **Calico VXLAN:** The actual data tunnel. Allows a worker pod to ping a control plane pod. |

### Worker Node - Inbound Rules

| Port | Protocol | Source (From) | Destination (To) | Simplified Purpose |
| :--- | :--- | :--- | :--- | :--- |
| **10250** | TCP | Control Plane Node | Worker Node | **Kubelet:** Allows the Control Plane to run `kubectl logs` and `kubectl exec` on this worker's pods. |
| **30000-32767** | TCP | Internet, Load Balancers | Worker Node | **NodePort:** Opens your actual deployed applications to the outside world. |
| **179** | TCP | Control Plane, Other Workers | Worker Node | **Calico BGP:** Shares the "map" of where pods live so this worker knows how to route traffic. |
| **4789** | UDP | Control Plane, Other Workers | Worker Node | **Calico VXLAN:** The actual data tunnel. Allows pods on other servers to ping pods on this server. |

*(Note: For a private testing environment, the easiest and safest configuration is to create a single inbound rule that allows **All Traffic** where the **Source** is the Security Group ID itself. This guarantees seamless internal K8s communication without exposing ports to the internet).*

## Phase 1: Common Server Preparation
> 🖥️ **RUN ON:** BOTH Control Plane AND Worker Nodes

### 1. Disable Swap & Configure Networking
```bash
# Disable Swap
sudo swapoff -a
sudo sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab

# Load necessary kernel modules
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
sudo modprobe overlay && sudo modprobe br_netfilter

# Set sysctl parameters for IP forwarding and bridging
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sudo sysctl --system
```

### 2. Install and Configure `containerd`
RHEL 9 requires pulling `containerd.io` from the Docker repository.
```bash
# Add Docker CE repo
sudo curl -L -o /etc/yum.repos.d/docker-ce.repo https://download.docker.com/linux/centos/docker-ce.repo

# Install containerd
sudo yum install -y containerd.io

# Create default configuration and enforce systemd cgroup driver
sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/g' /etc/containerd/config.toml

# Enable and start containerd
sudo systemctl enable --now containerd
```

### 3. Disable SELinux and Install Kubernetes Tools
```bash
# Set SELinux to permissive mode
sudo setenforce 0
sudo sed -i 's/^SELINUX=enforcing$/SELINUX=permissive/' /etc/selinux/config

# Add the official Kubernetes 1.35 Repository
cat <<EOF | sudo tee /etc/yum.repos.d/kubernetes.repo
[kubernetes]
name=Kubernetes
baseurl=https://pkgs.k8s.io/core:/stable:/v1.35/rpm/
enabled=1
gpgcheck=1
gpgkey=https://pkgs.k8s.io/core:/stable:/v1.35/rpm/repodata/repomd.xml.key
exclude=kubelet kubeadm kubectl cri-tools kubernetes-cni
EOF

# Install kubeadm, kubelet, and kubectl
sudo yum install -y kubelet kubeadm kubectl --disableexcludes=kubernetes

# Enable the kubelet service (it will wait in a crashloop until initialization)
sudo systemctl enable --now kubelet
```

## Phase 2: Control Plane Initialization
> 🖥️ **RUN ON:** ONLY the Control Plane Node

### 1. Initialize the Cluster
Initialize the cluster with the pod network CIDR that Calico expects by default (`192.168.0.0/16`).
```bash
sudo kubeadm init --pod-network-cidr=192.168.0.0/16
```
*(Copy the `kubeadm join` command output at the end of this process and save it for Phase 3).*

### 2. Setup `kubectl` Access
```bash
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
```

### 3. Install the Calico Network Plugin
Using the Tigera Operator to install Calico.
```bash
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.27.0/manifests/tigera-operator.yaml
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.27.0/manifests/custom-resources.yaml
```
Wait 2-3 minutes for the `calico-system` pods to start before proceeding to join worker nodes.

---

## Phase 3: Joining Worker Nodes
> 🖥️ **RUN ON:** ONLY the Worker Nodes

After completing **Phase 1** on the Worker Node, use the token generated by the Control Plane to join the cluster. 

*Note: You MUST use `sudo`.*
```bash
sudo kubeadm join <CONTROL_PLANE_IP>:6443 \
    --token <your-token> \
    --discovery-token-ca-cert-hash sha256:<your-hash>
```

*(If you lost the token, you can generate a new one from the Control Plane node by running: `kubeadm token create --print-join-command`)*

---

## Phase 4: Verification
> 🖥️ **RUN ON:** Control Plane Node

Verify that the worker has joined and all nodes have transitioned to the `Ready` state.
```bash
kubectl get nodes -o wide
```
Verify that all system pods (including CoreDNS and Calico) are in the `Running` state.
```bash
kubectl get pods -n kube-system
kubectl get pods -n calico-system
```
